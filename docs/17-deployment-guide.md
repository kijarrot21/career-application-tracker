## 1. Prerequisites

- **Node.js 20 or newer is recommended.** CI uses Node 22 (`.github/workflows/ci.yml`). The app targets Next.js 16.4.6.
- **npm** (ships with Node). The lockfile is `package-lock.json`; CI installs with `npm ci`.
- For local work you need no external database, no cloud account, and no API keys. All secrets are optional in development (`src/lib/env.ts`).
- Optional: a local Ollama instance (`OLLAMA_BASE_URL=http://127.0.0.1:11434`) if you want to exercise the local AI path. No AI provider is required for the app to boot.

## 2. Local development (default: embedded PGlite)

The default database is embedded PGlite, stored on disk at `PGLITE_DATA_DIR=./.data/pglite` (see `.env.example` and `src/lib/env.ts`). `DATABASE_URL` is empty by default, which selects PGlite.

1. Install dependencies: `npm ci` (or `npm install`).
2. Generate local secrets and apply migrations and seeds once: `npm run setup`.
   - `npm run setup` runs `scripts/setup.mjs` (writes a gitignored `.env.local` with a generated `BETTER_AUTH_SECRET` and `ENCRYPTION_KEY`) and then `scripts/migrate.mjs`.
   - This is the supported way to create the initial local database.
3. Start the dev server: `npm run dev` (Next.js on `http://localhost:3000` by default).

### 2.1 CRITICAL rule: never run setup or db:migrate while `next dev` is active

`npm run setup` and `npm run db:migrate` open the same `.data/pglite` directory. If `next dev` is running, the two processes corrupt the PGlite NODEFS data directory. This is upstream PGlite issue #884 (see `docs/PHASE_11_DEFECT_REGISTER.md`, DEF-11-009). There is no in place recovery.

Required sequence:

1. Stop `next dev` (Ctrl+C) and confirm the process has exited.
2. Run `npm run setup` or `npm run db:migrate`.
3. Restart `npm run dev`.

If the directory is already corrupted, queries abort with `RuntimeError: Aborted()` or `Failed query: CREATE SCHEMA ...`. Recovery means restoring from a backup copy of `.data`, or resetting the directory and re-running `npm run db:migrate` (which re-applies migrations and seeds). Local data written before the corruption is lost unless a backup exists.

## 3. Production style build and start (local, no cloud)

These commands are verified in CI and locally; they do not require a cloud database.

1. `npm run build` (Next.js production build). In production mode `src/lib/env.ts` requires `BETTER_AUTH_SECRET`; set it in the environment (or in `.env.local`) before building.
2. `npm run start` (serves the built app, default port 3000). Use a different port if `next dev` is still running, for example `PORT=3105 npm run start`.

Notes:

- The build uses the same embedded PGlite by default (`PGLITE_DATA_DIR`). Keep a single process per data directory.
- CI sets `PGLITE_DATA_DIR=memory://` and `BETTER_AUTH_URL=http://localhost:3105` for ephemeral builds; see section 5.

## 4. Configuration and feature flags

Copy `.env.example` to `.env.local` and fill only what you need. Development defaults are permissive; production requires `BETTER_AUTH_SECRET`.

Key variables:

| Variable | Default | Meaning and status |
|---|---|---|
| `DATABASE_URL` | empty | Empty selects local PGlite. A PostgreSQL URI selects a cloud database (NOT TESTED; see section 6). |
| `PGLITE_DATA_DIR` | `./.data/pglite` | On disk PGlite directory. CI uses `memory://`. |
| `BETTER_AUTH_SECRET` | dev placeholder | Required in production; generated by `npm run setup`. Use a `CHANGE_ME` placeholder only in scratch files, never a real key. |
| `BETTER_AUTH_URL` | `http://localhost:3000` | Public base URL for Better Auth. |
| `ENCRYPTION_KEY` | empty | 32 byte hex key for AES-256-GCM encryption of OAuth tokens; generated by `npm run setup`. |
| `PAYMENT_MODE` | `disabled` | Sandbox only when set to `sandbox`; live payments are not supported. |
| `SYNC_MODE` | `disabled` | Sandbox only when set to `sandbox`; live cloud sync is not supported. |
| `OPENAI_API_KEY`, `GEMINI_API_KEY`, `OLLAMA_BASE_URL` | empty / local | Optional AI providers. Live cloud provider calls are NOT TESTED here. |

No real or example secret values are included in this guide. Placeholders such as `CHANGE_ME` are intentionally nonfunctional.

### 4.1 Payments and sync are disabled by default

- `PAYMENT_MODE=disabled` and `SYNC_MODE=disabled` in `.env.example` and `src/lib/env.ts`. The `sandbox` value enables sandbox adapters only (`isMidtransSandboxConfigured`, `isStripeSandboxConfigured`, `isHybridSyncEnabled`). Live Midtrans and Stripe key prefixes (`Mid-server-`, `sk_live_`) are explicitly blocked without owner enablement. No real money payments or live cloud sync are implemented, configured, or tested.
- AI providers are optional. The project does not consume paid credits in CI or tests; real provider execution is BLOCKED pending owner approval.

## 5. CI only placeholder environment values

`.github/workflows/ci.yml` runs `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`, a Playwright browser install, and `npm run test:e2e` on push to `main` and on pull requests. Because `next build` runs with `NODE_ENV=production`, CI supplies throwaway values only for that job:

- `BETTER_AUTH_SECRET=ci-placeholder-secret-do-not-use-in-production-000`
- `BETTER_AUTH_URL=http://localhost:3105`
- `PGLITE_DATA_DIR=memory://`

These are disposable CI only names. They are not secrets and must never be used outside the CI job. The in memory database is discarded when the job ends.

## 6. Optional cloud PostgreSQL (NOT TESTED)

Setting `DATABASE_URL` to a PostgreSQL or Supabase connection URI switches the data layer from PGlite to PostgreSQL. The code path exists (`DATABASE_URL` is parsed in `src/lib/env.ts` and the `postgres` driver is a dependency), but no live cloud round trip has been exercised in this repository. Status: **NOT TESTED**. A blocking item recorded in `docs/PHASE_11_DEFECT_REGISTER.md` (BLK-04) is the absence of a cloud environment. Row level security is not implemented (DEF-11-006, accepted deferral); tenant isolation relies on application layer filters and composite foreign keys only. Do not assume cloud behavior equals local test results.

## 7. Backup and recovery caution

- Backups are **not automated and not drilled**. Status: **NOT TESTED**.
- The only local data is the PGlite directory (`./.data/pglite`) plus uploaded documents under `storage/documents/`. Copy both to a safe location before running migrations, upgrades, or switching database modes.
- Stop all processes using the data directory before copying it. Copying a live directory may produce an unusable snapshot.
- Point in time recovery, S3 or WORM object storage, and restore drills described in `docs/14-security-and-data-governance.md` are future options, not implemented features.
- Right to erasure removes a user's document directory (`deleteUserStorageDir`) and cascades database rows; a backup copy still contains that user's data until it expires or is purged. Account for this in any retention process.

## 8. What is not approved

- No production deployment is approved. This guide covers local and staging style runs only.
- No live payment processing, live AI provider consumption, live OAuth, or live cloud sync is approved or tested.
- Changing repository visibility, ownership, or licensing is out of scope for this phase (see `docs/19-license-and-ip.md`).
